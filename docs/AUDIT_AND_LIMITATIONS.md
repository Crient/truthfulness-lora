Raw datasets, adapters, model weights and caches were excluded. No model workloads, external network-based dataset downloads, or SLURM jobs were run for the independent review.

## 2. Errors and ambiguities corrected in the initial README

The user-supplied initial README was a useful narrative, but the source package permits several important corrections:

1. **Approach 1 parameters are recoverable.** The initial draft stated that the full Approach 1 notebook was unavailable. The audit ZIP includes notebook 03 and its runnable helper cells. Rank 16, alpha 32, dropout 0.05, all-linear modules, LR `2e-4`, microbatch 1, accumulation 4, FP16, `512` tokens, one epoch, 500-step evaluation and best-checkpoint loading are now directly sourced.
2. **The provenance status of category results must be explicit.** The reported 66-question result and 38-label matching were shared in the conversation; the category-matching script, fixed document-ID mapping, output tables and subgroup bootstrap script are missing from the package. These observations are valuable and **provisional**.
3. **Bootstrap intervals must name their computational convention.** The initial draft reported a F2-vs-Approach-1 MC2 CI around `[+0.01,+2.57]` pp. A new source-independent computation over sorted question IDs, fresh RNG seed 42 per comparison/task and 10,000 resamples gives `[+0.052,+2.512]` pp. The small difference is sensitive to finite RNG draws and input ordering. Older output remains labeled as historical, not replaced without disclosure.
4. **The complete benchmark has 817 items, not 100.** The pilot evaluated 100 documents, which must not be compared directly to full-817 means as a paired experiment.
5. **Zero-shot CLI is not demonstration-free.** `--num_fewshot 0` is recorded, but the TruthfulQA task's literal prompt embeds six Q/A demonstrations. Report both facts.
6. **MC2 is candidate-normalized likelihood mass.** Descriptions like “45.27% of generated answers are truthful” are incorrect.
7. **F2-Lite is not full Faithful Finetuning.** It omits the published F2's specialized weighting/layer-selection elements and does not use HaluEval hallucinated answers as negative pairs.
8. **Training is not controlled for compute/length/LR.** Attributing F2's small difference solely to a retrieval/grounding mechanism would be a causal overreach.
9. **Reported GPU peak units:** the original code divides bytes by `1024**3` but labels the output `GB`; this is better described as **GiB of peak allocated CUDA memory**, not total board usage or SLURM peak RSS.
10. **Historical SLURM status:** visible completion markers support successful run completion in logs; `sacct` was unavailable, so job allocation, accounting status and exit codes are not independently verified. Do not label these as accounting-verified `COMPLETED 0:0`.
11. **Source/weight revision distinction:** evaluation JSON records a model SHA; the training model and tokenizer loaded from offline cache without an explicit pinned revision. Avoid claiming fully pinned end-to-end model provenance.
12. **Historical notebook outputs:** some saved outputs refer to another user's directories or old hardware/environment. The newly sanitized notebook copies removed those outputs, and their historical status is documented separately. Do not derive current run details from them.

## 3. Statistical evidence classification

### Class A — independently reproduced within this exported dataset

- Full-run MC1 and MC2 aggregate means.
- Every baseline/A1/F2 sample count and document-ID match.
- Pairwise mean differences for all three pairs.
- 10,000-resample, seed-42 paired-bootstrap 95% percentile intervals for all three pairs and both tasks.
- MC1 improved/worsened/unchanged counts and MC2 positive/negative/near-zero difference counts.
- Pilot pair scores and bootstrap under the same documented procedure.

**Caveat:** These calculations prove internal consistency of the recorded benchmark outputs, not the integrity of the upstream dataset, the exact inference process, or scientific external validity.

### Class B — supported by source/log but not independently rerun

- Dataset split method and expected sizes.
- Approach 1 and F2-Lite target-construction logic.
- LoRA parameters, effective batch sizes, training requests, logging/checkpoint intervals.
- Trainer-reported runtime, loss trajectories, global steps, and best-checkpoint selection.
- Successful execution markers in logs.
- `lm_eval` task definitions and model-loading warning.

**Caveat:** No adapter weights, full raw dataset rows, exact model cache, hardware/accounting audit or immutable execution-time source hashes were included.

### Class C — research-chat reports requiring recovery of code/evidence

- Length-quartile medians, positive-change shares and changes.
- 817/817 category matching and all 38 category counts.
- 66/113/638 post-hoc group definitions as executable mapping.
- All context-dependent subcategory changes.
- 66-question paired bootstrap CIs.

The corresponding numerical tables are retained in [`RESULTS.md`](RESULTS.md) with explicit provenance labels. They should not be described as independently verified until source data, code and fixed IDs are archived.

### Class D — hypotheses / causal interpretations

- F2-Lite teaches the model to seek grounding on indexical questions.
- Short-answer supervision causes a particular calibration effect.
- Qwen thinking-template behavior explains MC2 differences.
- The method broadly reduces hallucinations outside the benchmark.

These remain **unproven**. They belong in discussion, not in a headline causal result.

## 4. Major threats to validity

| Threat | Why it matters | Practical control |
|---|---|---|
| Only one final training seed per approach | Adapter RNG can alter outcomes; question bootstrap ignores this | Multiple fully independent seeds; seed before adapter initialization |
| Confounded training recipes | F2 changes LR, length, record count and steps in addition to objective | Matched-budget component ablations |
| Task/prompt mismatch | Chat-format SFT vs plain Q/A likelihood evaluation | Paired prompt-format study with frozen model and candidate set |
| Post-hoc subgroup discovery | Extremes inspected before group definition; selective inference | Archive subgroup IDs now; evaluate prospectively on new data |
| Multiple comparisons | Several pairs, metrics, quartiles and categories explored | Declare one primary contrast; label others exploratory or adjust |
| Dataset/benchmark overlap unknown | Could bias cross-benchmark transfer claims | Exact/near-duplicate checks across full text and aliases |
| MC2 candidate normalization | Number, length and distribution of choices influence metric | Inspect option counts, token lengths and label distributions |
| Model/tokenizer revision uncertain | May alter log probabilities and adapter alignment | Pin immutable model and tokenizer snapshots + hashes |
| Evaluation vocabulary resizing warning | Different embedding/tokenizer alignment may influence results | Check source/config/shapes and repeat controlled loader audit |
| Chosen checkpoint uncertainty | Saved best val-loss checkpoints differ from final optimizer steps | Archive adapter hashes and checkpoint selection exactly |
| Hardware/version drift | Changes in libraries and kernels can change results | Export resolved env, CUDA/GPU, SLURM state, full training args |
| TruthfulQA exposure during research | Repeated inspection can overfit decisions to benchmark | Independent final held-out tasks and declared analysis plan |
| No free-generation benchmark | MC1/MC2 do not directly measure generated response truthfulness | Evaluate generated text with explicit human/automated rubric |

## 5. What would change our research conclusion?

The current conclusion is intentionally narrow: *Neither trained adapter beats the untouched model on the complete TruthfulQA MC1/MC2 point estimates. F2-Lite improves MC2 relative to Approach 1 on this benchmark.*

Evidence that could justify stronger conclusions includes:

1. Multiple training seeds with consistent effects and uncertainty reported across runs.
2. A controlled ablation isolating F2-Lite's direct/retrieval/grounded task mechanism from compute and hyperparameters.
3. Independently validated category joins and pre-specified subgroup outcomes.
4. Replication on an unseen context-dependent QA benchmark.
5. Independently scored *generated* answers, preferably blind or rubric-based, demonstrating fewer factual hallucinations with acceptable answer usefulness.

## 6. Research audit coverage and omissions

The ZIP audit manifest documented two export limitations: unavailable SLURM accounting and an omitted PDF walkthrough due to lack of a safe text extractor on Unity. The Markdown and extracted DOCX reports were included. The initial package contained ten per-task JSONL result files totaling roughly 32 MB uncompressed; **the GitHub documentation deliverable does not redistribute them**.

For future archival, preserve the full immutable private audit ZIP and its `SHA256SUMS`, and add a reproducibility annex with the raw 817-to-category join mapping, code commit, exact tokenizer/model SHA and verified adapter checksums before making a public release claim.
